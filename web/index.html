七条信号各响了多少次

一条注入可能同时命中多个信号，所以各条之和会大于触发次数。A/B/C 是战术层（同一个动作在重复），F/O/P 是方案层（动作在变、方案没动），M 是元层（提醒过 N 次仍无转向）。

方案层闸门（F / O / P / M）

阈值来自最近一次 apply 行；无效注入来自 futile 行。这些数字只描述「闸门按配置怎么判」，不证明它判对了。

提示之后，模型第一个动作是什么

描述量：只数「下一个动作落在哪一类」，不推断提示是否促成了它。

窗口内是否真的转去取得新事实

只在注入后固定步数窗口内看，超窗不算。中位步数只从这些「真转向」里算。

最近触发

时间会话轮/步 信号最热文件（累计/连续盲改）最热报错已搜测量
暂无记录

每个数字都能逐行数出来。触发次数、覆盖会话、信号分布来自 inject 行；「提示后首个动作」来自紧接着的那条 outcome 行；窗口内转向来自 change 行；测量回路来自 measure 行（它是「有没有反馈回路」的直接证据，跟任何动作分类无关）。

顶部那条红条只说「现在」。它只数最后一次 apply（也就是最近一次加载）之后的失败行——那之前的关闭/挂载失败已经被这次加载取代，不代表当下状态，只在这里列个数。

这些数字不证明什么。「提示后首个动作」只说明提示之后模型做了什么，它不能证明提示促成了这个动作，更不能证明它发现了缺陷——要回答那个问题需要对照组或历史回放。面板也不估算「省掉了多少 token」：那要先假设模型本来会失败，属于编数。
